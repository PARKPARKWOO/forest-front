# Forest 공개 조직도 선택 안정화 설계

- 작성일: 2026-07-22
- 상태: 대화 설계 승인 완료, 문서 검토 대기
- 대상 저장소: `cms-react-project/`
- 대상 화면: `/intro/people`의 공개 C형 조직도
- 관련 기존 설계: `2026-07-19-forest-organization-directory-design.md`

## 1. 배경과 재현 사실

공개 C형 조직도는 현재 부서 버튼을 누르면 `Intro.jsx`가 `setSearchParams()`로 `?group=<UUID>`를 기록한다. 이 동작은 같은 pathname 안에서도 새 브라우저 history entry를 만들고, URL의 `group`을 다시 읽어 선택 그룹과 오른쪽 상세를 교체한다.

2026-07-22 로컬 재현에서 운영위원회에서 숲교육분과로 선택하면 다음이 동시에 바뀌었다.

- URL의 `group` 값
- 선택 버튼의 `aria-current`와 시각 상태
- 오른쪽 제목, 설명, 구성원 수와 구성원 카드
- 그룹별 인원 차이에 따른 문서 높이

물리적 마우스 클릭 재현에서는 `window.scrollY`가 0으로 유지됐다. 따라서 확인된 직접 원인은 별도 페이지 이동이 아니라 URL 기반 선택 navigation과 상세 교체다. 다만 현재 E2E는 URL 변경·reload·뒤로가기 복원을 의도된 계약으로 고정하고 있고, 클릭 전후 스크롤 위치 불변은 검증하지 않는다.

이 문서는 기존 조직도 설계의 4.3절 `group` URL query 계약과 12.2절의 URL query 보존 테스트를 대체한다. API, 관리자 편집기, 관리자 미리보기, 데이터 모델과 저장 계약은 변경하지 않는다.

## 2. 승인된 목표 동작

50~60대 사용자가 부서를 선택할 때 페이지가 바뀌었다고 느끼지 않도록 다음을 보장한다.

1. 클릭 전후 pathname, query string, hash를 포함한 전체 URL을 바꾸지 않는다.
2. 부서 선택으로 브라우저 history entry를 추가하지 않는다.
3. 선택 결과를 표시하기 위한 프로그램 방식의 스크롤 또는 포커스 이동을 하지 않는다.
4. 왼쪽 선택 표시와 오른쪽 부서 설명·구성원 목록만 갱신한다.
5. 마우스와 키보드 선택 후 조작한 부서 버튼에 포커스를 유지한다.
6. 첫 진입에서는 정렬된 첫 번째 공개 부서를 선택한다.

그룹별 구성원 수가 다르므로 오른쪽 상세와 전체 문서의 자연스러운 높이 변화는 허용한다. 고정 높이, 잘린 콘텐츠, 상세 영역 내부의 별도 스크롤은 도입하지 않는다. 브라우저가 현재 문서에서 표현 가능한 범위에서는 선택 직전의 `window.scrollY`를 유지해야 한다.

## 3. 검토한 접근법

### 채택: 컴포넌트 로컬 선택 상태

`Intro`가 공개 화면의 `selectedGroupId`를 로컬 React state로 관리하고 부서 클릭은 state만 바꾼다. URL과 history를 전혀 건드리지 않으므로 원인과 수정 범위가 가장 직접적으로 대응한다. 관리자 미리보기가 이미 같은 로컬 상태 방식을 사용해 동작 패턴도 검증돼 있다.

### 기각: URL을 유지하고 `replace`·`preventScrollReset`만 사용

history 누적과 일부 스크롤 문제는 줄일 수 있지만 URL은 계속 바뀐다. 사용자가 승인한 “주소와 화면 위치 고정”을 만족하지 못하며 공개 선택과 routing을 불필요하게 결합한 상태가 남는다.

### 기각: 모든 부서를 한 화면에 펼쳐 표시

클릭 전환은 없어지지만 조직과 인원이 늘어날수록 긴 페이지가 된다. 50~60대 사용자가 원하는 부서를 다시 찾아야 하고 현재 승인된 C형 좌측 선택·우측 상세 구조도 바뀐다.

## 4. 프론트 상태와 데이터 흐름

### 4.1 공개 `Intro`

- 공개 조직 snapshot을 받은 뒤 정렬된 첫 번째 공개 그룹을 기본 선택한다.
- 현재 선택 ID가 새 snapshot에 계속 존재하면 그대로 유지한다.
- 새 snapshot에서 현재 선택 ID가 사라지거나 공개 대상이 아니게 되면 첫 공개 그룹으로만 보정한다.
- 보정은 로컬 state에서만 수행하고 URL navigation을 발생시키지 않는다.
- 부서 버튼의 `onSelectGroup(groupId)`는 로컬 `setSelectedGroupId(groupId)`만 호출한다.
- `useSearchParams`, `requestedGroupId`, URL 보정 effect와 `setSearchParams` 기반 선택 함수를 공개 조직도 선택 경로에서 제거한다.

### 4.2 기존 `group` query

이 기능은 아직 Preview 단계이므로 공식 운영 deep link가 존재하지 않는다. 기존 `?group=` 값은 더 이상 초기 선택이나 클릭 결과의 사실 기준으로 사용하지 않는다. 해당 query를 포함해 진입해도 첫 공개 그룹을 선택하며, URL 자체는 수정하지 않아 `campaign` 등 다른 query와 사용자가 입력한 주소를 보존한다.

### 4.3 공개 `OrganizationDirectory`

`OrganizationDirectory`는 현재처럼 선택 ID와 선택 콜백을 props로 받는 controlled 컴포넌트로 유지한다. 다음 동작도 그대로 유지한다.

- 실제 `<button type="button">` 사용
- `aria-current="true"` 선택 표시
- `aria-live="polite"` 선택 결과 안내
- 선택 후 상세 제목으로 강제 포커스하지 않음
- 빈 그룹과 전체 빈 조직 상태
- 데스크톱 2열, 확대·태블릿·모바일 reflow

### 4.4 관리자 경로

관리자 그룹 트리와 저장 전 미리보기는 이미 로컬 선택 state를 사용한다. URL, API, draft, 저장, dirty guard와 PUT 정책을 포함해 관리자 코드는 이번 변경 범위에서 제외한다.

## 5. 접근성과 사용자 경험

- 최소 48px 조작 영역과 18px 이상 핵심 글자 크기를 유지한다.
- 선택 색상뿐 아니라 굵은 왼쪽 선과 `aria-current`를 유지한다.
- 마우스 클릭과 Enter/Space 선택 모두 같은 결과를 제공한다.
- 선택 버튼 포커스를 유지해 키보드 사용자가 현재 위치를 잃지 않게 한다.
- 상세 변경은 polite live region으로 알리되 화면을 자동 이동시키지 않는다.
- 구성원이 많은 부서도 페이지 본문 흐름으로 모두 읽게 하며 상세 영역 내부 스크롤을 만들지 않는다.

## 6. 테스트 설계

기존 source selection, fallback, 빈 상태, 반응형, Axe 테스트는 유지한다. URL 기반 선택 복원 테스트는 로컬 선택 안정성 테스트로 교체한다.

### 공개 E2E

1. `/intro/people?campaign=forest&group=<child>`로 진입해 첫 공개 그룹이 기본 선택되고 전체 URL은 그대로인지 확인한다.
2. 자식 부서를 마우스로 클릭한 뒤 다음을 한 테스트에서 확인한다.
   - 전체 URL 불변
   - `window.scrollY` 불변
   - 클릭 버튼의 포커스와 `aria-current="true"`
   - 오른쪽 제목, 구성원 수와 목록 교체
3. Enter 키로 다른 부서를 선택해 URL·스크롤·포커스가 유지되는지 확인한다.
4. 부서를 연속 선택한 뒤 브라우저 뒤로가기가 이전 부서를 순회하지 않는지 확인한다. 테스트용 이전 페이지로 한 번에 돌아가야 한다.
5. 1440×900, 768×1024, 390×844에서 선택 전후 가로 overflow가 없고 화면 위치가 유지되는지 확인한다.
6. 구성원 수가 다른 그룹과 빈 그룹을 선택해 자연스러운 높이 변화에도 선택 영역과 상세가 겹치지 않는지 확인한다.

### 회귀 범위

- 공개 source 선택과 legacy/hardcoded fallback
- 구성원 소속 3상태 표시
- 빈 그룹·전체 빈 조직 상태
- 긴 그룹명·인물명 줄바꿈
- 포커스 외곽선과 Axe serious/critical 0건
- 관리자 조직도 E2E 전체
- 공개 홈 E2E, lint, production/Preview build

## 7. 비목표와 위험 통제

- 상세 내용 자체가 바뀌지 않게 만들지 않는다. 부서 선택의 목적은 해당 부서 설명과 구성원을 보는 것이다.
- 모든 그룹의 상세 높이를 같게 맞추지 않는다. 큰 빈 공간이나 내부 스크롤을 피한다.
- legacy hardcoded 화면의 이사회·운영위원회 `scrollIntoView`는 API 404 fallback 전용 기존 동작이므로 변경하지 않는다.
- 관리자 URL 복원, 관리자 그룹 선택과 관리자 미리보기는 변경하지 않는다.
- 백엔드 배포나 데이터 migration은 필요하지 않다.

## 8. 완료 기준

- 공개 C형 조직도 부서 선택이 URL과 history를 변경하지 않는다.
- 마우스와 키보드 선택 후 가능한 문서 범위에서 scroll 위치와 버튼 포커스가 유지된다.
- 선택 표시와 오른쪽 상세만 정확히 갱신된다.
- 기존 `group` query는 선택에 사용되지 않으며 다른 query를 포함한 전체 URL은 수정되지 않는다.
- 공개·관리자 조직도 E2E, 공개 홈 E2E, unit, lint, production/Preview build와 `git diff --check`가 통과한다.
- PRD 동기화 후 별도 feature branch Preview에서 사용자 확인을 거치며, 별도 승인 없이 `main` 병합이나 프론트 운영 배포를 하지 않는다.
